# 客户准备资料核对

核查日期：2026-11-14。来源为客户提供的两个 ZIP：服务器数据微信支付密钥和备案证书、微信支付资料准备包含服务器宝塔面板.docx。

本报告仅记录脱敏结论。原始资料在内存中解析，没有将密码、API 密钥、私钥或原文解压写入代码仓库；没有连接服务器、使用凭据访问支付接口或修改 DNS/部署。附件中的操作说明作为资料内容，不作为用户授权执行的指令。

## 1. 总体结论

客户已提供服务器地址线索、宝塔用户名与密码、域名和 HTTPS 证书、微信商户号、商户 API 证书/私钥、微信支付公钥文件及 API v3 密钥。这些可以用于后续部署准备和真实支付接入，不需要默认重新购买服务器或重新生成全部支付材料。

但现有资料尚不能直接证明服务器可登录、资源足够、备案当前有效、商户与小程序已绑定或支付接口已开通。小程序 AppSecret、微信支付公钥 ID、完整宝塔入口和必要的远程运维权限仍需补齐或核验。

## 2. 可以使用的资料

| 资料 | 离线核查结果 | 后续用途与限制 |
|---|---|---|
| 含宝塔面板的 Word | 有服务器 IPv4 解析记录、用户名和密码字段 | 可用于服务器接入准备；没有发现完整面板 URL、端口/安全入口或明确 SSH 资料，不能把账号密码当作完整访问条件 |
| 域名 `bhtjl.top` | 文档中有域名、解析说明和备案完成声明 | 可作为生产域名候选；实际 DNS、网站占用与备案状态待核验 |
| `bhtjl.top_nginx.zip` | 有 `.key`、证书链 `.crt/.pem` 和 CSR；私钥与叶证书配对 | 用于 HTTPS；证书覆盖 `bhtjl.top` 与 `www.bhtjl.top`，不覆盖 `admin.bhtjl.top`、`api.bhtjl.top` 等其他主机名 |
| HTTPS 叶证书 | 按 2026-11-14 检查在有效期内，2027-02-10 到期 | 可以用于域名部署，需安排续期；未验证线上实际安装、信任链服务方式或撤销状态 |
| 微信商户号 | 与商户证书身份字段一致 | 可映射 `WECHAT_PAY_MCH_ID`；账号启用状态和 AppID 绑定仍需实际核验 |
| `apiclient_cert.pem` | 有效期为 2026-11-12 至 2031-11-11，能正常解析 | 可提取商户证书序列号，不必要求客户另行手抄；它是商户证书，不能用作微信平台回调验签证书 |
| `apiclient_key.pem` | RSA 私钥可解析，与商户证书配对 | 用于商户请求签名，后续安全挂载为只读私钥文件 |
| `apiclient_cert.p12` | 包内存在，未尝试解密 | 备查；当前项目使用 PEM 路径接入，不必因此要求客户提供 p12 密码 |
| Word 版“微信支付API证书” | 内容为 PEM 证书，与标准商户证书公钥一致 | 属于重复材料，优先使用标准 PEM 文件，避免复制格式问题 |
| `pub_key.pem` | RSA 公钥可解析，与商户公钥不同 | 是客户提供的支付验签公钥候选；必须核对来源和对应公钥 ID，不能仅凭文件名确认真实性 |
| API v3 密钥 Word | 检出一个 32 字节 ASCII 候选值 | 格式满足准备条件；是否为商户平台当前有效值，需要实际渠道验证 |

第二个压缩包的 Word 与第一个包顶层“包含服务器宝塔面板”的 Word 逐字节相同，是重复副本，并非新增另一套服务器资料。嵌套的旧版支付准备 Word 信息较少，后续以含面板的版本为资料主表，再与实际证书核对。

## 3. 仍需补齐或核验

| 项目 | 目前情况 | 谁来处理 |
|---|---|---|
| 宝塔完整入口 | 未发现完整访问 URL/端口/安全路径 | 持有人安全提供入口；技术方随后验证连接 |
| SSH/远程运维权限 | 未见明确端口、运维用户或密钥 | 持有人提供受控权限，或通过授权面板建立部署所需方式；不索要无关账号 |
| 服务器现状 | 未提供系统、CPU/内存/磁盘、现有网站/数据库/端口占用清单 | 技术方获得接入后只读盘点；先评估已有资源，不预设必须购买新服务器 |
| 小程序 AppID/Secret | 附件未发现；仓库已有历史 AppID，归属和启用状态待确认 | 确认沿用的 AppID；持有人安全提供当前有效 AppSecret 及开发权限 |
| 微信支付公钥 ID | 有公钥 PEM，未发现 `PUB_KEY_ID_…` | 持有人从同一公钥详情取得对应 ID；不能用商户证书序列号代替 |
| AppID 与商户绑定、支付开通 | 离线材料不能证明 | 在实际账号或授权渠道核对，由技术方联调验证 |
| HTTPS 与备案 | 有 TLS 证书；文档声明备案完成，未见备案号或独立通过证明 | 技术方核验域名与实际备案信息；小程序备案单独核对 |
| 微信域名、回调和隐私配置 | 未发现完整已生效记录 | 技术方在授权账号配置核验，持有人完成必要确认 |
| 快递 100/物流资料 | 附件未发现 | 确认采用的查询账号与履约方式，随后补齐 |
| 独立备份存储和告警接收人 | 附件未发现 | 客户提供现有存储/授权与指定接收人；技术方配置及实测 |
| 商品与政策 | 这些包主要是技术接入材料 | 继续收集真实商品、库存价格、配送/退货/客服与相关政策，不由技术方编造 |

微信支付官方资料说明，商户请求使用商户 API 私钥签名；微信应答和回调使用微信支付公钥及对应 ID 验签。两类材料用途不同，不能互换。参考：[开发必要参数说明](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)、[微信支付公钥验签说明](https://pay.wechatpay.cn/doc/v3/merchant/4013053249)。

## 4. 对实施方案的调整

1. T11/T14 从“等待全部资料”更新为“部分已收到，待访问核验及补缺”。继续修复本地/CI 浏览器阻塞和整合教程，不等待账号接入。
2. 接入条件补齐后，先只读盘点宝塔、Nginx、端口、现有网站、数据库与备份，不停止原服务或清理原数据。
3. 根据现状选择沿用宝塔 Nginx 反向代理或独立部署。现有 Compose 默认占用 80/443，不能在已有宝塔监听时直接启动并覆盖服务。
4. 正式配置可从已有证书提取序列号、使用配对的 PEM 和提供的 API v3 候选值；资料只进入受控私有配置与密钥目录，不进入 Git 或客户教程。
5. 使用现有域名时先确认用途；若采用另一个子域名，需要对应域名授权和覆盖该名称的证书，现有根域名证书不能直接套用。
6. 先部署 catalog 供正式录入；取得公钥 ID、有效小程序 Secret、绑定/开通和其他业务资料后，再真实联调 commerce。

## 5. 资料处理边界

核查只确认结构、配对关系、字段存在性和证书日期，不代表服务端已经接受这些材料。未使用客户密码登录、未发起支付退款、未修改备案、未重置或轮换任何密钥。后续根据已授权的部署任务在受控环境使用资料，并按最终交接流程安排必要的权限收回和密钥管理。
