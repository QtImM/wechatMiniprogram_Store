# 人工事项与交付状态

本清单严格区分客户授权事项与尚未验证的技术工作。当前是交付候选代码，不是已上线并签收的商城。

## 需要客户或账号持有人处理

| 事项 | 需要提供或操作什么 | 原因 |
|---|---|---|
| 服务器、域名和备份存储 | 购买或提供已有资源；授权部署人员访问服务器和 DNS，提供证书方案 | 资源归客户所有，产生费用及账号授权需持有人处理 |
| 微信小程序和支付 | 确认“陕铺”平台名称、备案和经营类目；授予开发/体验/商户协作权限；安全提供渠道资料 | 需要主体及账号持有人权限，部分步骤需扫码或实名确认 |
| HBuilderX 发行 | 有权限的持有人完成一次 HBuilderX 登录，或提供已授权的构建环境 | 本机开发编译成功，但发行命令明确提示须先登录；脚本没有伪造成功 |
| 运营政策与真实资料 | 确认商品/规格/价格/库存、运费配送范围、退货地址、客服、经营资质和协议内容 | 开发者不能替客户编造商品或经营承诺 |
| 财务实单与签收 | 安排真实小额付款/退款验收和对应财务核对，最终确认交付 | 必须核对真实渠道与到账，不能用 Mock 代替 |

客户不需要自己写代码、拼部署命令或排查迁移。上述权限和资料齐备后，发布、配置、数据升级、备份演练和测试继续由技术交付方执行。

- 后端 11 模块构建与 160 项测试通过，包含录入模式入口保护、实际 Security 过滤链、库存回退、指定订单评价、完整迁移门禁与真实 RSA 公钥验签等测试。
- 管理后台类型检查、生产构建通过，更新后生产依赖扫描 195 项、已知报告为零。
- 交付工具在独立 Python 3.12 与固定密码库版本上 19 项测试通过；小程序地址 5 项用例及全量迁移清单一致性检查通过。
- HBuilderX 最新源码开发编译成功；发行构建因账号登录未完成而被工具正确拒绝，不使用开发构建冒充正式发行产物。
- 多项 API/权限/生产配置静态检查通过；新增 CI 修复了远端 main 原本在安装 Node 缓存前找不到 pnpm 的失败原因。
- 后端依赖补丁已构建验证；原始扫描仍有 Spring MVC 和 MyBatis 内嵌 OGNL 两组报告，当前应用未发现相应受影响功能入口。完整评审在 `docs/acceptance/2026-11-04-dependency-security-review.md`，不能把它改写为“后端零漏洞报告”。
