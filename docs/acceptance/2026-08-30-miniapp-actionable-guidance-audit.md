# 小程序可执行引导盘点

## 结论

已检索 `shop-miniapp/pages` 与 `shop-miniapp/components` 中全部 `util.toast`、`uni.showToast`、`uni.showModal` 调用。共发现约 60 处提示。并非每个提示都应跳转：只有用户必须前往其他页面或执行明确下一步时，才应提供操作入口；表单格式错误和当前页选择错误应留在原地并引导到对应控件。

## 应保留当前页引导

这些情况跳转页面不能解决问题，正确做法是让用户在当前控件补充或修正信息；后续可增强为红框/自动聚焦，但不应强行跳走。

| 场景 | 位置 | 原因 |
|---|---|---|
| 商品规格未选完整、数量或库存不足 | `pages/goods/goods.vue:421-451` | 规格选择器就在当前商品页，用户需补选规格或调整数量 |
| 购物车未选商品 | `pages/cart/cart.vue:350` | 勾选框就在当前页，跳转会中断结算意图 |
| 地址姓名、手机、省市区、详细地址格式不完整 | 两个 `addressAdd` 页面 | 对应输入项就在当前表单 |
| 评论、反馈、售后原因、退货物流字段不完整 | `commentPost`、`feedback`、`orderDetail` | 对应输入项在当前表单或弹层 |
| 登录协议未勾选 | `pages/auth/btnAuth/btnAuth.vue:55-71` | 勾选入口及协议链接就在登录页 |

## 不应强制跳转的提示

网络失败、服务暂不可用、领取优惠券失败、会员信息加载失败、支付结果确认中等属于可重试或等待状态。现有页面会保留重试按钮、原操作入口或订单查询入口；无需自动跳转，避免用户丢失上下文。
