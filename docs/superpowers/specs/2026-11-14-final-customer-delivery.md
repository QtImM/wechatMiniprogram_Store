# 陕铺最终客户交付补充规格

日期：2026-11-14。继承 `2026-11-03-customer-release-closure.md`，以实际远端比较和 CI 结果补充实施要求。本文件描述完成条件，不表示已经实现或验收。

## 1. 版本与范围

- 技术基线：`codex/customer-delivery-closure` 的 `bf549ea3980ba2ce87a69cfbc4a5b280b9eaed2d`。
- 吸收教程和名称：`feat/shanpu-admin-guide` 的 `f81b0d1cfdac38974b9bea11743957923db1f3c9`。
- 先 M1 正式商品录入，再 M2 完整实物商城；同一生产库和素材持续使用，隔离测试不得接收正式客户录入。
- 继续默认单商户、实物、单库存池、整单单包裹、微信支付、整单售后退款、现有基础营销；以客户既有合同为最终范围依据。
- 分销、付费会员、虚拟课程、部分退款、拆包、多仓和 ERP 不作为默认新增范围；如合同已有承诺，必须形成差异任务，不能直接隐藏入口当作完成。

## 2. 必须关闭的当前缺口

1. 浏览器实际登录、路由和角色操作闭环通过，保留失败诊断；不以提高超时或改成拦截演示接口代替修复。
2. 教程与实际候选界面一致，明确 catalog 限制、默认下架、展示名配置、回退范围和运营权限。
3. 未交付的虚拟履约能力在后台、导入、服务端上架和公众展示/交易入口均受到一致限制；旧数据先报告，不能擅自改客户经营数据。
4. 既有规格要求的政策链接、配置版本与审计须逐项对照实际代码；存在缺口就实施或记录客户确认的范围调整，不能因已有展示配置表而直接视为全项完成。
5. M1 可在无支付物流凭据时使用正式安全配置部署；公众和交易入口关闭，仍保留后台身份与权限保护。
6. 完整迁移清单及校验和、空库初始化、旧库副本升级、重复执行与失败保护通过；验收表不再依赖单个旧迁移版本。
7. 候选源码、精确镜像包、配置版本和测试证据可关联；验收过的包必须保留，生产不得再次解析依赖重建。
8. 数据库和素材成套备份、加密、独立故障域副本、实际恢复、失败/过期通知及应用回滚均实测。
9. 微信、支付退款、物流、发货信息管理适用要求、隐私和提审配置在客户实际账号中核验；真机和实单证据不能由 Mock 替代。

## 3. 完成定义

M0 技术候选：整合后的固定版本通过完整 CI、浏览器和隔离恢复验证，留下可部署产物及限制清单。

M1 客户录入：真实 HTTPS 后台中，客户独立录入单/多规格商品和导入文件；账号权限有效，图片和数据重建后保留，成套备份可恢复；交付教程、账号与录入签收记录。M1 不代表公开销售。

M2 商城交付：保留 M1 正式数据，在真实渠道完成购买、履约、退款、对账；生产发布、运维演练、培训、观察及客户签收完成。

结果仅使用“通过 / 失败 / 待验证 / 不适用（有依据）”。每项记录版本、环境、时间、执行人及证据；影响资金、权限、隐私和客户数据的未解决问题阻止对应阶段放行。
