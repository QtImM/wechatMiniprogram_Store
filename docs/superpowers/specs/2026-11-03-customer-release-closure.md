# 陕铺客户交付收口规格

日期：2026-11-03。基线：main `92d83bddcc14a43f7f8183a0a3d1260238c0c45c`。

## 目标与边界

在既有 Java/Spring Boot、Vue 管理端、uni-app 小程序基础上收口交付。交付须包括客户独立运营、真实交易、受控部署、监控、备份恢复、发布回滚和签收证据。先交付后台录入，再开放商城交易；两个阶段使用同一套生产数据，不临时用开发环境接收客户正式录入。

v1.0 默认交付单商户、实物商品、单库存池、整单单包裹、微信支付、整单售后退款、基础优惠券/满减/包邮。付费会员、分销、积分、直播、拼团、多仓、ERP、部分退款、拆包和虚拟课程履约均不默认纳入。客户若已明确购买这些能力，需要先对照合同重新定范围和工期，不能仅以隐藏入口代替合同交付。

## 运行模式

使用 `app.delivery-mode=catalog|commerce`，环境变量名 `APP_DELIVERY_MODE`，仅作为计划中的接口命名，当前尚未实现。未知值拒绝启动；对外部署必须显式配置。环境仍使用 prod/staging，保留原安全要求。

| 能力 | catalog | commerce |
|---|---|---|
| 后台账号、权限、审计 | 必须可用 | 必须可用 |
| 分类、素材、商品、SKU、库存、内容、店铺展示配置 | 允许并验收 | 允许并验收 |
| 用户登录、浏览及交易 API | 应用与网关均关闭 | 按权限开放 |
| 微信支付/退款回调 | 关闭 | 精确路径匿名接收，必须验签解密及业务核验 |
| 支付、退款、对账、自动履约任务 | 不启动 | 按配置启动 |
| Mock 写入口 | 关闭 | 关闭 |
| 微信、支付及物流资料 | 未启用模块不强制要求 | 所有启用渠道按实际模式校验 |
| 新商品状态 | 默认下架 | 默认下架，显式上架 |

catalog 不能读写真实交易业务；允许保留业务表以便后续平滑升级。正式录入时仅给客户商品运营账号，超级管理员另行保管。商品首次开放交易前统一检查分类、图片、SKU、价格、库存和配送政策。

## 必须补充的产品规则

- 后台店铺展示配置持久化：展示名、Logo、简介、客服、政策链接及版本；不存支付密钥。仅授权管理员修改，长度/图片/链接校验，记录审计并刷新相关页面缓存。明确不修改微信平台账号名称或备案信息。
- 商品与内容的预览、保存、上架行为必须一致，避免将保存误认为上架；实时预览不能宣称完全等同真机效果。
- 商品回退默认只恢复展示字段；不得用历史快照覆盖交易后库存。库存恢复使用独立增减调整、原因和审计，并检验版本及并发。
- 正式数据与演示种子隔离，正式环境不生成测试用户、订单、营销异常或未确认的商品；客户正式录入数据在后续升级中保留。

## 完成定义

M1：客户通过真实 HTTPS 后台独立录入商品、上传图片和 Excel 导入；越权被拒绝；交易不可调用；重建后数据及图片保留；数据库与素材可恢复。

M2：M1 数据保留，在体验版及实际生产渠道完成登录、商品、购物车、下单、微信支付、发货、收货、售后退款和对账；必要的微信发货信息管理已按账号适用情况落实；真实生产切流、告警、回滚、备份恢复通过；客户签收。

两个里程碑均需记录实际 commit/镜像摘要、配置版本、迁移清单、测试结果、负责人和客户证据。代码存在、历史测试通过、静态脚本通过均不能替代本次运行验收。
