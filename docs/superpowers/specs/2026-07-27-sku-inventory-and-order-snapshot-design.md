# SKU 库存与订单商品快照设计

## 目标

将交易模块从 SPU 库存和 `MockData` 回退切换到真实 SKU 库存：提交订单时锁定并扣减库存，取消或超时关闭时回补；订单明细保存真实 SKU 商品快照。

## 范围

- 商品模块提供 SKU 查询、可售校验、原子扣减和回补能力。
- 交易模块只通过商品模块读取商品/SKU 快照和变更库存。
- 下单时校验 SPU/SKU 归属、商品上架状态和 SKU 库存。
- 订单项保存 SPU ID、SKU ID、名称、图片、规格、成交价、数量和小计。
- 取消订单与超时关闭仅在订单状态从待付款成功变更后回补 SKU 库存。

## 明确不做

- 不新增独立锁库表、库存流水表或库存中心。
- 不修改支付、物流与小程序页面流程。
- 售后退款审核通过后不自动回补库存；需在未来的“退货入库”流程中按实际入库数量回补。本期只保留该业务边界，不提供入库接口。

## 设计

`ProductInventoryService` 位于商品模块，封装对 `product_spu` 和 `product_sku` 的访问。它返回不可变的商品快照，并通过 `UPDATE product_sku SET stock = stock - ? WHERE id = ? AND stock >= ?` 实现原子扣减；回补仅允许按真实 SKU ID 增加库存。

`TradeProductService` 仅协调交易语义：读取真实快照、调用库存服务扣减或回补，不再引用 `MockData`。`TradeOrderService` 在创建订单项前读取 SKU 快照并扣减库存；现有事务失败时由 Spring 回滚扣减。订单关闭流程读取订单项中的 `skuId`，仅在待付款订单状态条件更新成功后执行一次回补。

## 验收标准

1. 不存在、下架、SKU 不属于 SPU 或库存不足的商品不能提交订单。
2. 提交订单只扣减指定 SKU，不影响同一 SPU 的其他 SKU。
3. 取消或超时关闭待付款订单只回补一次指定 SKU。
4. 订单详情始终使用订单项快照，即使商品随后修改。
5. 退款审核通过不回补库存，日志或文档明确其依赖未来退货入库流程。
